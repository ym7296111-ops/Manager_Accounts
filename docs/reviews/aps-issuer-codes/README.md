# أكواد المُصدرين وقائمة «كود الخطاب» — حزمة مراجعة

حزمة لقطات **قبل** فتح طلب الدمج، مأخوذة من معاينة محلية ببيانات **خيالية**:
`npm run preview:ui` (ضبط المشروع) و`npm run preview:aps` (شاشة الإدخال). هذه
المعاينة تستبدل Supabase والمصادقة والصلاحيات ببيانات في الذاكرة، فهي تُثبت
التنسيق والنصوص والحالات — **لا** تثبت PostgREST أو RLS أو سلوك PostgreSQL.
قواعد القاعدة تغطيها المراجعة/التدقيق خارج هذا الحزمة.

## ما تغيّر

### 1) تبويب «أكواد المُصدرين» في ضبط المشروع

تبويب جديد في `/settings/project` (آخر تبويب، بعد «عام»)، بصلاحية
`project.settings:manage` (نفس بوابة الشاشة: `RequireCapability`).

| العمود | المعنى                                                       |
| ------ | ------------------------------------------------------------ |
| الكود  | حرفان إنجليزيان (مثل `YM`) — هوية السطر، تُكتب مرة واحدة     |
| الاسم  | اختياري؛ إن تُرك فارغاً يُخزَّن الكود نفسه ويُعرض الكود وحده |
| الحالة | نشط / معطّل                                                  |

- «إضافة كود جديد» → نافذة بحقلين: «الحرفان (مثال: YM)» و«الاسم / الوصف
  (اختياري)». الحقل يقبل حرفين إنجليزيين فقط ويحوّلهما إلى أحرف كبيرة، ويُمنع
  التكرار (فريد على `upper(code)` في القاعدة، ويُصنَّف الخطأ كـ`duplicate`).
- «تعديل» يعدّل **الاسم فقط**؛ الحرفان يُعرضان كنص ثابت مع سطر يشرح أنهما هوية.
- «تعطيل/تفعيل» بدل الحذف: لا يوجد زر حذف في الواجهة إطلاقاً، والجدول لا يمنح
  `delete` أصلاً. سبب ذلك أن `letters.issuer_code` يشير إلى السطر، فحذفه يفقد
  الخطابات السابقة معناها.

### 2) حقل «كود الخطاب» في شاشة الإدخال

- حُذف الحقل النصي الذي كان يقبل `YM:63` نهائياً.
- صار الشكل `[ YM ▼ ] : [ 63 ]`: قائمة منسدلة تعرض الأكواد **النشطة** بصيغة
  `YM — ياسر`، ثم النقطتان مطبوعتان ثابتتين (لا تُكتبان)، ثم حقل رقمي يقبل
  الأرقام فقط (والأرقام العربية لا تدخله).
- الحقل الرقمي معطّل حتى يُختار المُصدر؛ وإلغاء اختيار المُصدر يلغي الزوج بدل
  أن يترك رقماً بلا مُصدر.
- عند الحفظ يُدمج الحقلان داخلياً في عمود واحد: `issuer_reference` = `YM:63`.
- مسودة تحمل كوداً عُطّل بعد إنشائها تُبقي القيمة ظاهرة كخيار «(غير نشط)» مع
  شرح أحمر، ولا يُحفظ عليها — بدل أن يضيع الكود بصمت.

### 3) ما لم يتغيّر

تفرد `issuer_reference` داخل السنة المالية، تجميد الحقل بعد الاعتماد، عدم إرسال
`p_letter_date`، رقم النظام (EPS) كما هو، السطر التلقائي للفترة كما هو، والاعتماد
حصراً عبر `aps_approve_letter`. **لا ترحيل SQL جديد** في هذه الحزمة.

## RLS: لا شيء مطلوب تغييره

`supabase/migrations/20261117000000_aps_issuers.sql` (مدموج) ينشئ السياسات
الثلاث مسبقاً:

| السياسة                           | لمن             | الشرط                                                |
| --------------------------------- | --------------- | ---------------------------------------------------- |
| `issuers_letter_readers_select`   | `authenticated` | `aps_can_read_letters() or aps_can_create_letters()` |
| `issuers_project_settings_insert` | `authenticated` | `can_manage_project_settings()`                      |
| `issuers_project_settings_update` | `authenticated` | `can_manage_project_settings()`                      |

مع `grant select, insert, update on public.issuers to authenticated` وبلا
`delete`. أي أن من يملك `project.settings:manage` يقرأ ويضيف ويعدّل ويُعطّل، بلا
حاجة إلى ترحيل جديد.

> ملاحظة صريحة: مجموعة التدقيق المحلية (PostgreSQL + 95 فحصاً) غير متاحة في هذه
> الجلسة، فلم يُعَد تشغيلها هنا. لم يتغيّر أي ملف SQL في هذا العمل.
