# لقطات مراجعة «قفل أرصدة أول المدة» (Data Freeze)

لقطات من معاينة المتصفح الحقيقية (`npm run preview:ui` → `http://localhost:4173`) بالعربية واتجاه RTL،
بعد تنفيذ القفل من الواجهة نفسها: مفتاح الحالة ← نافذة تأكيد ← «قفل الأرصدة».

```bash
npm run preview:ui            # في نافذة أولى
LD_LIBRARY_PATH=/tmp/nsslibs node /tmp/freeze-shot.mjs
```

| الملف                        | العرض | المحتوى                                                                 |
| ---------------------------- | ----- | ----------------------------------------------------------------------- |
| `01-locked-desktop-1280.png` | 1280  | شريط تحذيري، مفتاح أحمر «الأرصدة مقفلة - لا يمكن التعديل»، وحقول معطّلة |
| `02-locked-mobile-390.png`   | 390   | الحالة نفسها على هاتف حقيقي: المفتاح سطر مستقل، بلا تجاوز أفقي          |

المعاينة تعمل على `src/dev/preview/memorySupabase.ts` (بيانات في الذاكرة). المحاكي يقلّد سياسة RLS
أيضاً: الكتابة في سنة مقفلة تُرفض بـ`42501`، والحذف يُفلتر إلى صفر صفوف، وهو ما تفعله قاعدة البيانات.
لكن **التنفيذ الحقيقي** يبقى في `supabase/migrations/20261112000000_opening_balances_freeze.sql`
ويُتحقق منه في `scripts/audit/database.mjs` وعلى سيناريو E2E في `e2e/tests/fiscal-settings.spec.ts`.
