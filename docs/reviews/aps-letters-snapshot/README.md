# مراجعة استعراض خطابات APS ولقطات أسماء السطور

اللقطات من واجهة الاستعراض الفعلية داخل معاينة محلية ببيانات **خيالية بالكامل**. الشريط الأصفر يوضّح أن المعاينة لا تتصل بـ Supabase ولا تثبت المصادقة أو PostgREST أو RLS في بيئة حقيقية.

## عقد اللقطة والترتيب المطلوب

- يحفظ حارس كتابة السطر اسم المخزن واسم التصنيف من الخادم عند الإدراج وعند كل حفظ مسموح لسطر مسودة؛ الأسماء المرسلة من العميل لا تُعتمد. إذا أُعيدت تسمية مرجع أثناء المسودة، تُلتقط التسمية الجديدة عند حفظ ذلك السطر مجددًا. الاعتماد أو الإلغاء يجمّد السطور بأسمائها الأخيرة المحفوظة.
- قراءة السطر تكشف الاسمين المحفوظين للقارئ المسموح له، حتى إن لم يكن لديه حق قراءة الدليل. لا أُضيفت أكواد للمراجع، ولا تغيّرت منح الجداول أو سياسات RLS.
- الترحيل الجديد يفترض فراغ `letter_lines`؛ المستخدم أفاد بأن جدولي الخطابات والسطور فارغان في الإنتاج، ولم نتصل بالإنتاج للتحقق. إذا كانت هناك سطور عند التنفيذ يفشل الترحيل دون تعبئة أو تغيير البيانات؛ يُراجع الأمر صراحةً بدل تشغيل backfill أو تعطيل الحراسات. يأخذ `ALTER TABLE` قفل PostgreSQL المعتاد.
- يُطبّق الترحيل الجديد **قبل** نشر الواجهة التي تقرأ العمودين. لا يشكّل هذا الطلب إذنًا بالدمج أو التطبيق على الإنتاج.

## الاختبارات وحدودها

- تدقيق PostgreSQL 17 المحلي يعيد الترحيلات الـ55 ويختبر إلزام الاسمين، رفض تزويرهما، إعادة الالتقاط، ثباتهما بعد الاعتماد والإلغاء، مسار التسوية، الرؤية مع حجب الدليل، وفشل الترحيل الذري مع سطور موجودة.
- اختبارات Vitest تغطي طلبات القراءة وحالات الشاشة. اختبارات `npm run test:e2e:aps-preview` تشغّل متصفحًا حقيقيًا فوق المعاينة الاصطناعية؛ لا تحل محل فحص PostgREST وRLS وE2E في بيئة Supabase حقيقية.
- لم تُجرَ هنا أي عملية ترحيل أو نشر أو فحص على الإنتاج.
