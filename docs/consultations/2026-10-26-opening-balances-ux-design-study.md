## 0. الخلاصة التنفيذية (TL;DR)

**الحكم:** المشكلة المبلَّغ عنها حقيقية ومُثبتة في الكود، لكنها ليست الوحيدة في الشاشة. تحويلها إلى «سطور متفرّقة + منتقي تصنيفات» صحيح، ويُصلح في الطريق ثلاث ثغرات أخطر من الإطالة البصرية: **سطور أرصدة تختفي من الإجماليات**، و**حذف بلا أثر تدقيقي**، و**مسودات تُفقد بلا تنبيه**.

### القرارات المعتمدة في هذه الوثيقة

| #   | القرار                                                                 | الأثر                                                  |
| --- | ---------------------------------------------------------------------- | ------------------------------------------------------ |
| D1  | الافتراضي: **سطور محفوظة فقط**، ولا حقول فارغة لكل تصنيف               | يقلّص DOM من `مخازن × تصنيفات` إلى `صفوف مُدخلة فعلاً` |
| D2  | الإضافة عبر **Combobox مضمّن باختيار متعدد (Chips)**، لا Modal         | يقلّل القفز السياقي ويصلح للموبايل                     |
| D3  | **السطور اليتيمة** تُعرض في قسم «أرصدة تحتاج مراجعة» وتبقى في الإجمالي | يمنع اختفاء مبالغ من مجموع المحطة                      |
| D4  | **حذف فعلي** لسطر محفوظ + تأكيد + تدقيق `opening_balance.deleted`      | يغلق ثغرة محو رصيد بلا سجل                             |
| D5  | الحفظ = **المضاف + المعدَّل** (upsert قائم)، والحذف **إجراء مستقل**    | لا تركيبة طلبات قابلة للفشل الجزئي                     |
| D6  | الأرصدة **السالبة ممنوعة**؛ `CHECK (amount >= 0)` يبقى كما هو          | قرار عمل نهائي                                         |
| D7  | تفكيك المكوّن إلى Settings + Row + Picker (+ ملفات مساندة)             | 603 سطراً الآن، والميزة ستضيف لا تُقلّص                |
| D8  | حارس مسودات: `beforeunload` + اعتراض **تبويبي** المشروع والضبط المالي  | يمنع فقدان إدخال غير محفوظ                             |
| D9  | **P0 + P1 فقط**؛ لصق Excel ونسخ السنة السابقة مؤجّلان                  | نطاق مضبوط وقابل للمراجعة                              |

### أهم خمس نتائج تقنية

1. **اللوحات المطوية تُركَّب كاملة.** الإخفاء بـ `hidden` فقط (`OpeningBalancesSettings.tsx:397` و`:503`)، وكل تصنيف ورقي يُنشئ `<input>` (`:508`) — أي أن الأسوأ من التمرير هو **حجم DOM** غير المرئي.
2. **إعادة الحساب على كل ضغطة مفتاح.** `warehouseTotal` و`changedRows` و`invalidDraft` و`stationTotal` تُحسب لكل مخزن في كل render (`:119`, `:133`, `:407`, `:414`, `:423`).
3. **السطور اليتيمة موجودة اليوم.** `is_leaf` مُشتق بـ trigger (`20261104040000_classifications_schema.sql:173`)، فإضافة تصنيف فرعي تحت تصنيف له رصيد تُخرجه من القائمة بلا تحذير — ويُستبعد من الإجمالي، **ويبقى في قاعدة البيانات**.
4. **الحذف بلا تدقيق.** الـ trigger مُعرَّف على `after insert or update` فقط (`20261110000000…sql:226`)، و`audit_action` لا يحتوي قيمة حذف. الصلاحيات موجودة (`:241`, `:324`)، أي أن الحذف ممكن تقنياً وبلا أثر.
5. **المسودات تضيع بصمت.** `OpeningBalancesSettings` يُلغي التركيب عند تبديل التبويب (`FiscalSettings.tsx:92-98`)، وكذلك عند تبديل تبويب المشروع (`ProjectSettings.tsx:136-148`).

### التوصية النهائية

| العنصر         | التوصية                                                                                  |
| -------------- | ---------------------------------------------------------------------------------------- |
| الإدخال        | سطور متفرّقة، مفتاحها `classification_id` داخل المخزن، مرتبة دائماً حسب كود التصنيف      |
| الإضافة        | Combobox مضمّن + Chips + زر «إضافة (N)»؛ بعد الإضافة ينتقل التركيز إلى أول حقل مبلغ جديد |
| الحفظ          | لكل مخزن كما اليوم؛ يرسل المضاف + المعدّل فقط؛ السطر المضاف الفارغ **يُهمَل**            |
| الحذف          | فوري لسطر محفوظ بعد تأكيد؛ سطر مضاف يُزال محلياً بلا تأكيد                               |
| اليتيم         | قسم مراجعة للقراءة فقط + قابل للحذف + محسوب في الإجمالي                                  |
| الإجماليات     | تُحسب من الصفوف الفعلية (محفوظة + مسودات + يتيمة) لا من كل التصنيفات                     |

| التقسيم        | PR للبيانات (ترحيل + hook)، ثم PR للواجهة (المكوّنات + i18n + الاختبارات)                |

## 3. نموذج التفاعل الجديد

### 3.1 الشكل العام

```
┌ المحطة الرئيسية (ST-01)                    إجمالي المحطة: 12,500.00 ┐
│                                                                     │
│ ┌ مخزن المواد الخام (WH-001)                    الإجمالي: 12,500.00 ┐│

│ │──────────────────────────────────────────────────────────────────││
│ │ CLS-001  حديد وصلب                 [ 1,250.00 ]            🗑     ││
│ │ CLS-004  أخشاب                      [ 3,000.00 ]            🗑     ││
│ │ CLS-009  مواد كيميائية              [ 8,250.00 ]            🗑     ││
│ │──────────────────────────────────────────────────────────────────││
│ │ [+] إضافة تصنيف                              [ حفظ الأرصدة ]      ││
```

عند فتح المخزن بلا أرصدة:

```
│ │ لا توجد أرصدة مسجّلة لهذا المخزن بعد.                            ││
│ │ [+] إضافة تصنيف                                                   ││
```

### 3.2 نموذج الحالة في الواجهة

يُستبدل `drafts: Record<"year:warehouse:classification", string>` (`:159`) بنموذجين صريحين لكل مخزن:

```ts
/* مفتاح الصف داخل المخزن هو classification_id، لأن قيد التفرد
   في قاعدة البيانات هو (fiscal_year_id, warehouse_id, classification_id). */
interface WarehouseDraftState {
  readonly values: Readonly<Record<string, string>>; // النص كما كتبه المستخدم
  readonly added: ReadonlySet<string>; // سطور أُنشئت هذه الجلسة ولم تُحفظ
}
```

يُشتق منه صف العرض:

```ts
type BalanceRowKind = 'persisted' | 'added' | 'review';

interface BalanceRowModel {
  readonly classificationId: string;
  readonly code: string;
  readonly name: string;
  readonly kind: BalanceRowKind;
  readonly balanceId: string | null; // موجود للمحفوظ فقط (يحتاجه الحذف)
  readonly amountText: string;
  readonly dirty: boolean;
  readonly invalid: boolean;
  readonly reviewReason?: 'not_leaf' | 'inactive'; // للمراجعة فقط
}
```

**لماذا فصلنا `values` عن `added`؟**
`values` يخدم التعديل على المحفوظ والمضاف بنفس الآلية، و`added` يحدد دلالة الحذف (محلي بلا تأكيد أم فعلي بتأكيد) ويحدد ما يُرسل عند الحفظ، ويخدم شارة «لم يُحفظ».

### 3.3 قواعد الحفظ

| الحالة                            | تُرسل؟ | ملاحظة                                                       |
| --------------------------------- | ------ | ------------------------------------------------------------ |
| سطر مضاف بمبلغ صالح (بما فيه `0`) | ✅     | يُحفظ ويختفي وسم «جديد»                                      |
| سطر مضاف فارغ                     | ❌     | يُهمَل ويُزال بعد نجاح الحفظ، مع تلميح «سطر فارغ — لن يُحفظ» |
| سطر محفوظ لم يُعدَّل              | ❌     | لا طلب بلا تغيير                                             |
| سطر محفوظ عُدِّل (بما فيه تفريغه) | ✅     | التفريغ = `0`، وليس حذفاً — الحذف يحتاج زراً صريحاً          |
| سطر مراجعة (يتيم)                 | ❌     | للقراءة فقط                                                  |

- يُرسل الطلب الواحد لكل مخزن كما اليوم (`handleSaveWarehouse`, `:261`) عبر upsert قائم.
- يُعطَّل الزر عند: لا تغيير، أو وجود قيمة غير صالحة، أو طلب جارٍ.
- بعد النجاح: تُحذف مسودات **الصفوف المرسلة فقط** من الحالة (لا تُمسّ السطور التي أُضيفت أثناء الطلب) — وهذا امتداد لسلوك موجود في `:299-305`.

### 3.4 الإجماليات والعدّادات

- **إجمالي المخزن** = Σ(الصفوف المحفوظة في هذا المخزن + المسودات + صفوف المراجعة) — أي **من الصفوف الفعلية**، لا بالمرور على كل التصنيفات كما اليوم.
- **إجمالي المحطة** = Σ إجماليات مخازنها.
- **عدّاد المخزن** = «عدد التصنيفات المُدخلة من أصل عدد الأوراق النشطة» + «عدد صفوف المراجعة» عند وجودها.
- تبقى الأرقام `bigint` بالسنتات و`formatCents` كما هي.

## 4. منتقي التصنيفات (ClassificationPicker)

### 4.1 لماذا مضمّن لا Modal

| المعيار          | Modal                               | Combobox مضمّن           |
| ---------------- | ----------------------------------- | ------------------------ |
| إضافة سطر واحد   | قصّ ولصق سياقي + إغلاق              | فتح/اختيار/إغلاق فوري    |
| الموبايل         | نافذة + لوحة مفاتيح + قائمة = تصادم | Popover فوق الحقل مباشرة |
| إضافة 10 تصنيفات | ممكن باختيار متعدد                  | ممكن باختيار متعدد       |
| التركيز          | يحتاج إدارة تركيز معقدة             | يعود للحقل التالي مباشرة |

القرار: **مضمّن**، مع تحويله إلى ورقة سفلية (`bottom sheet`) على الشاشات الضيقة جداً عبر أصناف `sm:`.

### 4.2 العقد

```ts
interface ClassificationPickerProps {
  /** أوراق نشطة فقط، قادمة من useActiveLeafClassifications (استعلام واحد مخزَّن). */
  readonly options: readonly ActiveLeafClassification[];
  /** المُضاف والمحفوظ مسبقاً في هذا المخزن — يُستبعد من القائمة. */
  readonly excludedIds: ReadonlySet<string>;
  readonly busy: boolean;
  readonly onAdd: (classificationIds: readonly string[]) => void;
  readonly onClose: () => void;
}
```

### 4.3 السلوك والاختيار المتعدد

1. زر «إضافة تصنيف» يفتح Popover أسفل الزر ويُركّز حقل البحث تلقائياً.
2. البحث **محلي** على `options` المحمّلة مسبقاً — لا طلب شبكة لكل حرف.
3. `Enter` أو النقر يضيف التصنيف كـ **Chip** داخل المنتقي (لا يُنشأ صف فوراً).
4. إزالة Chip بـ `×` أو `Backspace` عند حقل فارغ.
5. زر «إضافة (N)» يُنشئ N صفاً مرتبة حسب الكود، ويُعلن عبر `aria-live` «أُضيف N سطراً»، ويُنقل التركيز إلى حقل مبلغ أول صف جديد.
6. `Esc` يغلق ويتجاهل Chips غير المُثبتة (إجراء غير مدمّر).
7. يُمنع التكرار: `excludedIds` = المحفوظ ∪ المضاف.

### 4.4 البحث العربي

يبحث في **الكود والاسم** بعد تطبيع:

| المدخل                   | التطبيع          |
| ------------------------ | ---------------- |
| أ / إ / آ                | ا                |
| ة                        | ه                |
| ى                        | ي                |
| التشكيل (َ ُ ِ ّ ْ …)    | يُزال            |
| مسافات زائدة وسوابق `ال` | تُطبَّع للمقارنة |
| حروف لاتينية             | `toLowerCase`    |

والفرز بـ `Intl.Collator('en', { numeric: true })` نفسه المستخدم في `byCode` (`useClassifications.ts:115`) حتى يتصرف `CLS-1000` كما في شاشة التصنيفات.

### 4.5 لوحة المفاتيح وإمكانية الوصول

| المفتاح              | السلوك                    |
| -------------------- | ------------------------- |
| ↑ / ↓                | تنقل بين الخيارات         |
| Enter                | تبديل Chip للخيار الحالي  |
| Esc                  | إغلاق وإلغاء Chips        |
| Backspace (حقل فارغ) | إزالة آخر Chip            |
| Tab                  | خروج طبيعي إلى زر الإضافة |

- `role="combobox"` على الحقل، `aria-expanded`، `aria-controls`، `aria-autocomplete="list"`، `aria-activedescendant`، والقائمة `role="listbox"` والخيارات `role="option"` مع `aria-selected`.
- حالة «لا نتائج» وحالة «كل التصنيفات مضافة» بنصوص صريحة.
- زر الإضافة معطّل مع `title` توضيحي إذا لم يبق أي تصنيف متاح.

### 4.6 الحالات الحدّية

| الحالة                    | التصرف                                                                                       |
| ------------------------- | -------------------------------------------------------------------------------------------- |
| آلاف التصنيفات            | فرز + بحث محلي، عرض أول 50 نتيجة مع «عرض المزيد»، بلا virtualization                         |
| لا أوراق نشطة إطلاقاً     | زر الإضافة معطّل + نص يوجّه إلى تبويب «التصنيفات» (نص فقط، لا رابط: التبويب داخل نفس الصفحة) |
| تصنيف عُطِّل أثناء الجلسة | يبقى صفه إن كان محفوظاً وينتقل إلى «مراجعة»؛ يختفي من قائمة الإضافة                          |
| مخزن معطّل                | يظل مرئياً (كما اليوم) مع وسم «معطّل» وصفوفه تُعامل كالمعتاد                                 |

## 5. السطور اليتيمة (أرصدة تحتاج مراجعة)

### 5.1 التعريف ومصدر الحقيقة

**السطر اليتيم** = صف في `opening_balances` موجود، لكن تصنيفه ليس ضمن «الأوراق النشطة» المستخدمة في المحرّر. ينشأ من:

| السبب      | كيف يحدث                                                    |
| ---------- | ----------------------------------------------------------- |
| `not_leaf` | إضافة تصنيف فرعي تحت تصنيف له رصيد → `is_leaf` يصبح `false` |
| `inactive` | تعطيل التصنيف من شاشة التصنيفات                             |

> **مستحيل بالتصميم:** الحذف. `opening_balances.classification_id` و`warehouse_id` مُعرَّفان `on delete restrict` (`20261110000000…sql:167-172`)، فلا يمكن أن يصبح الصف يتيماً بحذف مرجعه.

### 5.2 الكشف — الدمج بدل استعلام ثانٍ

يُوسَّع `OPENING_BALANCE_SELECT` (`useFiscalSettings.ts:20`) بدمج **مع تلميح المفتاح الأجنبي** وفق قاعدة `postgrest-embeds.test.ts`:

```ts
const OPENING_BALANCE_SELECT =
  'id, fiscal_year_id, warehouse_id, classification_id, amount, created_at, updated_at, ' +
  'classifications!classification_id(id, code, name, is_leaf, is_active)';
```

**لماذا الدمج؟**

- **لقطة واحدة متسقة**: `is_leaf` تأتي مع الصف نفسه، فلا يمكن أن تُقرأ الصفوف في لحظة والتصنيفات في لحظة أخرى تغيّرت بينهما.
- طلب واحد بدل تحميل شجرة التصنيفات كاملة في شاشة لا تحتاج الشجرة.
- `classifications` عليها سياسة `can_manage_project_settings()` نفسها، فالدمج لا يوسّع نطاق القراءة.

**بديل مرفوض:** `useClassifications()` لبناء خريطة أسماء — يضيف طلباً كاملاً ويخالف قاعدة «كل استعلام له سبب عرضي».

**أثر جانبي مقصود:** `OPENING_BALANCE_SELECT` يُستخدم أيضاً في `.select()` بعد الـ upsert (`useFiscalSettings.ts:401`)، فستعود الصفوف المحفوظة بالشكل المدمج نفسه. هذا يُبقي كاش React Query متجانساً بعد الحفظ، لكنه يُلزم أن يكون نوع الصف في `onSuccess` (`:410`) هو نوع القراءة نفسه، لا `OpeningBalance` الخام.

يلزم تابع قراءة متسامح جديد `parseOpeningBalances(raw)` على نمط `parseClassifications`/`parseStationsDirectory`: يُسقط الصفوف المشوّهة ولا يُفرغ الشاشة، ويصنّف كل صف إلى `persisted | review` مع `reviewReason`.

### 5.3 العرض

```
│ │ ── أرصدة تحتاج مراجعة (1) ─────────────────────────────────────│
│ │ ⚠ CLS-014  مواد تعبئة        تصنيف له تصنيفات فرعية   [ 500.00 ]│
│ │   راجع شجرة التصنيفات: إمّا تعيده ورقةً أو تنقل الرصيد لتصنيف فرعي.│
```

- يظهر **داخل لوحة المخزن** أسفل السطور العادية، بخلفية `bg-warning/5` وحدود مميزة.
- **للقراءة فقط**: لا حقل إدخال، لا تعديل.
- **الحذف مسموح** عبر نفس مسار الحذف المؤكَّد والمدقَّق — لأنه المسار الوحيد لتصحيح خطأ بنيوي.
- **محسوب في إجمالي المخزن والمحطة** بلا استثناء.

### 5.4 ما لا نفعله الآن

- لا نمنع إضافة تصنيف فرعي لتصنيف له رصيد، ولا نمنع تعطيله — هذا تغيير في شاشة التصنيفات وخارج النطاق (P2). النص الإرشادي يكفي مؤقتاً.
- لا ننقل الأرصدة تلقائياً إلى التصنيفات الفرعية — قرار محاسبي لا تقني.

## 6. مسار الحذف والتدقيق

### 6.1 القرار

| العنصر       | القرار                                                          |
| ------------ | --------------------------------------------------------------- |
| النوع        | حذف فعلي (`DELETE`) لسطر محفوظ                                  |

### 6.3 الترحيل المقترح

الملف: `supabase/migrations/20261111000000_opening_balances_delete_audit.sql`

```sql
-- قيمة جديدة للتدقيق على الحذف (نفس نمط السطر 8 في ترحيل الأرصدة)
alter type public.audit_action add value if not exists 'opening_balance.deleted';

-- توسيع الدالة لتقرأ OLD عند الحذف
create or replace function public.audit_opening_balance_write()
returns trigger
language plpgsql
security definer
set search_path = pg_catalog, public
as $$
begin
  if tg_op = 'DELETE' then
    insert into public.audit_logs (actor_id, action, entity, entity_id, metadata)
    values (
      auth.uid(),
      'opening_balance.deleted'::public.audit_action,
      'opening_balances',
      old.id::text,
      jsonb_build_object(
        'fiscal_year_id', old.fiscal_year_id,
        'warehouse_id', old.warehouse_id,
        'classification_id', old.classification_id,
        'old_amount', old.amount,
        'new_amount', null
      )
    );
    return old;
  end if;

  insert into public.audit_logs (actor_id, action, entity, entity_id, metadata)
  values (
    auth.uid(),
    'opening_balance.updated'::public.audit_action,
    'opening_balances',
    new.id::text,
    jsonb_build_object(
      'fiscal_year_id', new.fiscal_year_id,
      'warehouse_id', new.warehouse_id,
      'classification_id', new.classification_id,
      'old_amount', case when tg_op = 'UPDATE' then old.amount else null end,
      'new_amount', new.amount
    )
  );
  return new;
end;
$$;

revoke all on function public.audit_opening_balance_write()
  from public, anon, authenticated, service_role;

drop trigger if exists opening_balances_audit_write on public.opening_balances;
create trigger opening_balances_audit_write
  after insert or update or delete on public.opening_balances
  for each row execute function public.audit_opening_balance_write();
```

### 8.1 مصادر الخطر

| المصدر                                  | النتيجة اليوم                                                          |
| --------------------------------------- | ---------------------------------------------------------------------- |
| تبديل تبويب داخل «الضبط المالي»         | إلغاء تركيب الشاشة → فقدان كل المسودات                                 |

| الانتقال عبر الشريط الجانبي             | فقدان (router يعتمد `BrowserRouter` بلا data router، فلا `useBlocker`) |

### 8.2 الحل

1. `UnsavedChangesGuard.tsx`: مزوّد واحد في `ProjectSettings` يوفّر `registerGuard(id, isDirty)` و`confirmNavigation(next)`.
2. الشاشة تسجّل `isDirty` المشتق من الـ hook.
3. أزرار التبويب في **المستويين** (المشروع/الضبط المالي) تستدعي `confirmNavigation` قبل التبديل؛ عند الرفض يبقى التبويب كما هو.
4. نافذة التأكيد: «لديك تغييرات غير محفوظة» + زرّان: **«العودة للحفظ»** و**«مغادرة بدون حفظ»** (لا «حفظ ثم مغادرة»: الحفظ قد يفشل جزئياً ويُنتج حالة غامضة).
5. `beforeunload` يُسجَّل فقط عند `isDirty` (سابقة قائمة: `GeneralSettings.tsx:427`).

### 8.3 القيود المعروفة (تُوثَّق لا تُخفى)

- **الانتقال عبر الشريط الجانبي غير معترَض** بهذا التصميم. المعالجة الكاملة تحتاج إمّا data router (`createBrowserRouter` + `useBlocker`) أو حفظ المسودات في `sessionStorage` واستعادتها — وكلاهما خارج نطاق P0/P1.
- الحفظ الجزئي المسموح: نجاح حفظ مخزن لا يمسّ مسودات مخزن آخر، وهذا مقصود.
- `beforeunload` نصّه من المتصفح ولا يُترجم — حد معروف.

### 10.2 RTL والموبايل والوصول

- الخصائص المنطقية فقط: `ms-*`/`me-*`/`start-*`/`end-*`، بلا `left`/`right`.
- Popover بعرض `min(100%, 22rem)` و`max-height: 20rem` مع تمرير داخلي، ويُحوَّل إلى ورقة سفلية على الشاشات الضيقة.
- أهداف لمس ≥ 44px، وزر حذف منفصل بصرياً عن حقل المبلغ.
- `inputMode="decimal"` و`min={0}` و`step="0.01"` كما اليوم.
- تمييز السطر الجديد بإطار مؤقت (يُحترم `prefers-reduced-motion`).
- إدارة التركيز: بعد الإضافة → أول مبلغ جديد؛ بعد الحذف → زر حذف السطر التالي أو عنوان المخزن.
- البانر الحالي (`FiscalBanner`) يوفّر `role="status"`/`role="alert"` — يُعاد استخدامه لا استبداله.

## 15. معايير القبول

1. مخزن بلا أرصدة لا يعرض أي حقل إدخال، ويعرض زر إضافة.
2. مخزن بـ 50 تصنيفاً و3 أرصدة يعرض 3 حقول فقط.
3. المنتقي لا يعرض تصنيفاً مضافاً أو محفوظاً مسبقاً، ويطابق البحث العربي والكود.
4. الاختيار المتعدد يُضيف عدة سطور بعملية واحدة، ويُعلن ذلك لقارئ الشاشة.
5. الحفظ يرسل المضاف + المعدّل فقط، ويعيد القيم منسّقة بسنتين.
6. القيم السالبة مستحيلة الإرسال من الواجهة، والقيد في قاعدة البيانات لم يتغيّر.
7. حذف سطر محفوظ ينشئ صف تدقيق `opening_balance.deleted` بمعرّف الصف والمبلغ القديم.
8. الرصيد اليتيم مرئي في قسم المراجعة، غير قابل للتعديل، ومحسوب في إجمالي المخزن والمحطة.
9. مؤشر «N من M» صحيح، ولا يتغيّر بتغيّر طيّ اللوحات.
10. تبديل التبويب مع مسودة يوقف المستخدم؛ الحفظ ثم التبديل يمرّ بلا تحذير.
11. `npm run lint` و`typecheck` و`test` و`build` خضراء، واختبار الترحيلات أخضر.
12. لا أثر على `src/pages/settings/OpeningBalancesSettings.tsx` الأصلي من حيث أرقام المبالغ: نفس `bigint` ونفس `formatCents`.
